# Antigravity Rules

Follow the documentation inside the docs folder.

Do not redesign the project architecture.

Do not rename folders.

Do not rename APIs without updating documentation.

Generate code feature-by-feature.

Each feature must be fully working before starting another.

Never generate placeholder code.

Never leave TODO implementations unless explicitly requested.

Always generate

- Backend
- Frontend
- API
- Types
- Validation
- Tests (if requested)

Keep commits small.

Do not modify unrelated files.

Reuse existing components whenever possible.

Follow the repository folder structure.

Prefer composition over duplication.

Always use TypeScript strict mode.

Never use any.

Never introduce unnecessary dependencies.

If a required package is missing, explain why it is needed before adding it.

Generate production-ready code.
